# ETHONLINE-90 — Integration, Review and Submission

## Objective

Merge only independently verified sponsor work into one coherent Delegated Recovery journey and produce an auditable Continuity submission.

## Entry criteria

Do not begin until at least Hedera core acceptance is green and sponsor branches have independent review results.

## Integration order

1. shared domain/types and mandate model;
2. Hedera authority + settlement core;
3. hero UX;
4. World request verification;
5. Ledger authority/escalation layer if green;
6. end-to-end browser path;
7. negative/adversarial path;
8. submission evidence and 2–4 minute demo.

## Required final demo beats

- owner creates mandate for booking #193;
- authority is demonstrably scoped;
- agent acts inside mandate;
- USDC recovery settlement is visible;
- out-of-policy attempt is blocked;
- owner revokes or rejects escalation;
- proof/receipt is understandable;
- before/after Continuity delta is explicit.

## Final review attacks

- Continuity eligibility / baseline diff;
- sponsor-specific qualification;
- security and replay;
- false/overbroad identity claims;
- simulated-vs-live truth;
- UI legibility on mobile and desktop;
- demo timing and narrative.

## Never

- merge a sponsor branch merely because its code exists;
- hide a failing sponsor requirement in the final demo;
- add a late sponsor integration that breaks the coherent journey;
- perform unattended production/mainnet deployment.
