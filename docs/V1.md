# V1 demo-complete

This file is the finish line for the current hackathon version.

If all items below are true, the project is ready to be presented as a coherent `v1`.

## v1 product story

The `v1` demo proves that:

- an issuer can create scarce service-slot inventory under their own conditions
- Person A can buy one slot and become the current holder
- Person A can list that right for resale when issuer policy allows
- Person B can buy the listed right and become the new current holder
- the issuer can see the holder change and still control the lifecycle
- the issuer must mark the pass **used** at redemption so it cannot be used twice

## v1 acceptance

### Issuer

- can initialize the demo
- can mint live slots
- can see active inventory
- can see who currently holds each live pass
- can freeze and unfreeze when needed
- can mark a pass **used** at redemption

### Person A

- can browse live slots
- can book a slot
- can see that they now hold it
- can list it for resale when policy allows
- stops looking like the valid holder after Person B buys it

### Person B

- can see a resale opportunity
- can buy the listed pass
- can see that they are now the current holder
- can redeem only while the pass is still active

### Shared trust

- only live inventory looks bookable
- resale movement is visible to issuer and guests
- once `USED`, the pass no longer looks active
- the previous holder cannot still use the same pass
- proof links or tx ids can be shown for the key steps

## What still has to be true before calling it done

1. **Resale copy must stay honest**
   - do not overstate seller proceeds unless the exact settlement has been proven against testnet results
   - if needed, use softer wording such as HTS royalty applies on secondary movement and verify final settlement from tx proof

2. **The issuer redemption step must be obvious**
   - the demo should clearly show that the issuer closes the lifecycle by marking the pass used

3. **Anti-double-use must be credible**
   - after resale, Person A is no longer the valid holder
   - after `USED`, the pass is closed

4. **Proof must exist**
   - fill `docs/TX-LOG.md` with real tx ids and HashScan links for:
     - `F1`
     - `F2`
     - `F4`
     - optional `F3`

## Not required for `v1`

These are important, but they are not blockers for calling the demo complete:

- sign up / log in
- fiat or multi-currency checkout
- marketplace-style listing discovery beyond the current flow
- configurable royalty editor in the UI
- refund / cancel (`F7`)
- gift / direct transfer flow separate from resale

## Judge-facing summary

`v1` is complete when the team can show one full business-controlled lifecycle:

1. issuer creates the inventory
2. Person A buys
3. Person A resells
4. Person B buys
5. issuer redeems by marking used
6. the final state is visible and provable
