TRANSACTION MAPPING

A. Initialize token
- TokenCreateTransaction

B. Initialize topic
- TopicCreateTransaction

C. Mint slots
- TokenMintTransaction
- one metadata payload per slot

D. Associate buyer
- TokenAssociateTransaction

E. Primary booking
- TransferTransaction
- buyer sends HBAR to treasury
- treasury sends NFT serial to buyer
- after success submit HCS BOOKED

F. Resale listing
- app-only listing record
- validate holder owns serial
- save listing
- submit HCS LISTED

G. Resale purchase
- TransferTransaction
- buyer sends HBAR to seller
- seller sends NFT serial to buyer
- HTS royalty fee enforces issuer royalty
- after success mark listing inactive
- submit HCS RESOLD

H. Freeze
- TokenFreezeTransaction
- after success submit HCS FROZEN

I. Unfreeze
- TokenUnfreezeTransaction
- after success submit HCS UNFROZEN

J. Mark used
- TokenBurnTransaction
- after success submit HCS USED

AUTO-ASSOCIATE RULE

For booking and resale purchase:
- before transferring an NFT to guestA or guestB, check token association
- if not associated, perform TokenAssociateTransaction first
- if already associated, continue normally
- this should happen automatically inside the API route

API ROUTES

Every Hedera-writing route must include:
export const runtime = "nodejs"

POST /api/init
- idempotent
- create token if missing
- create topic if missing
- if already created, return existing ids
- return tokenId and topicId

POST /api/mint-slots
- idempotent by default
- load public/demo-slots.json
- if slots already seeded, return existing serials
- only mint duplicates if explicit reseed=true or reset flow is used
- persist slot records in Redis

POST /api/associate
- associate Guest A or Guest B with token if needed
- no-op if already associated

POST /api/book
- validate serial is AVAILABLE
- selected actor must be Guest A or Guest B
- auto-associate if needed
- execute primary booking transfer
- submit BOOKED
- return txId and HashScan link

POST /api/resale-list
- validate current holder owns serial
- validate status is HELD and not FROZEN and not USED
- save active listing in Redis
- submit LISTED
- return listing

POST /api/resale-buy
- validate active listing exists
- selected buyer must be Guest A or Guest B
- auto-associate if needed
- execute resale transfer
- mark listing inactive
- submit RESOLD
- return txId and HashScan link

POST /api/freeze
- issuer-only
- freeze holder
- submit FROZEN

POST /api/unfreeze
- issuer-only
- unfreeze holder
- submit UNFROZEN

POST /api/mark-used
- issuer-only
- burn serial
- submit USED

GET /api/mirror
- proxy selected Mirror reads if needed for frontend convenience
