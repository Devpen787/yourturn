# Operation-owned mandate read

The ordinary `loadActiveRecoveryMandate` and pre-claim canonical projection intentionally reject an odd booking authority version. A claimed operation owns that odd version until completion or safe abandonment. Its consumer needs an explicit authority check during this interval; it must never fake an even version or bypass the ordinary guard.

`loadRecoveryOperationAuthority({store, operation, revalidateMutableAuthority})` is that separate read-only boundary. It requires the exact durable operation identity, intent, phase, revision, lease and fence; the actual owned odd version; the exact active current pointer; matching active mandate owner/agent/booking/generation/stable version/expiry; canonical signed fields and recomputed EIP-712 digest; matching recovered/public signer; a positive int64 net minimum; and the supported testnet USDC resale scope. Missing or malformed state denies.

It surrounds the mandatory trusted fresh mutable authority callback with operation/version/current-pointer reads and rereads the complete active record. The callback receives frozen mandate fields and must check current booking holder/status/provider and signer enrollment. This module does not implement those external reads. Observable revoke/replacement/takeover/lease/record/version/clock drift denies; the original observation window is at most five seconds. Returned records are frozen snapshots with `executionPermit:false`.

This function does not reserve, renew, take over, release, begin, retry or submit an effect. A caller still uses the existing atomic `beginRecoveryOperationEffect` transition, supplies the current fully bound intent and validates the requester. An effect already started may use this read only to revalidate existing authority; another begin-effect is forbidden by the existing state machine. After revoke/expiry, this loader fails; receipt-only completion uses the existing separate completion primitive and can still reconcile a started effect without new authority.

No ordinary-loader input option was widened, no store wrapper replaces odd values with even values, and no existing transition/Lua was changed. This does not install the canonical World/Hedera consumer or resolve real account/chain/provider facts. Point-in-time reads are not a consensus lock.

Synthetic local state tests exercise negative boundaries. Hosted disposable Redis tests activate a synthetic mandate with a public test key, claim the real operation, read owned authority, begin an effect once, reject authority on revocation, and complete only a synthetic receipt. No device, real credentials, real signature/transaction, production write or sponsor LIVE qualification is involved. Exact source/evidence requires separate independent review before consumer composition.
