# Current mandate owner HTTP boundary

New testnet-only routes wrap the independently qualified current-pointer/revoke primitive. They do not replace prepare/activate, import canonical projection, use hardware, sign, execute recovery, or claim action authority.

- `GET /api/ledger/recovery-mandate/current?tokenId=0.0.…&serial=…` requires a signed app guest session plus a fresh raw stored user with exactly matching ID/email and explicit `appRole:user`. Missing/corrupt/unavailable users fail closed; the legacy role/persona inference does not establish this ownership. It returns only the owner's pointer with `CURRENT_POINTER_OBSERVATION`, `authorityVerified:false` and `executionPermit:false`. An `active` pointer is not proof of unexpired signed authority or current chain eligibility. Responses are not cached.
- `POST /api/ledger/recovery-mandate/revoke` additionally requires exact same Origin (and same-origin Fetch Metadata when present), JSON body limited to4096 bytes, no query, and exactly `{tokenId,serial,mandateId,digest}`. Serial is a canonical positive safe-integer string. Owner identity is never accepted from the body. Missing/nonowned pointers share a404; stale mandate identity is409. The existing exact CAS prevents a stale request revoking a replacement. Repeating the same revocation is safe. No operation/effect reservation is released or rewritten.

Stored user identity is reread before the mutation. Revocation returns `effectsCancelled:false`: it prevents later guarded authority checks but cannot reverse an effect that already started. Unknown post-dispatch failures return503 `REVOKE_OUTCOME_UNKNOWN_RELOAD_CURRENT`; reload the current pointer and retry only the same exact mandate identity when appropriate. No rollback, ID regeneration or blanket retry of effects is implied.

The cookie signature remains the existing application authentication mechanism. Test handlers inject synthetic signed identity and public stored-user records; they do not qualify a real authenticated user session. Dedicated CI also exercises the actual Next routes for unauthenticated/cross-origin/method rejection without credentials or mutations. Model and actual disposable Redis tests cover owner/body/role/fallback/missing data, replacement races, lost replies and concurrent idempotent revocation. The old current/operation suites stay unchanged.

A caller needing execution authority must still use the guarded signed-mandate loader and actual canonical resolver. This component does not implement the World/Hedera consumer or prove the physical40→30 replacement/revocation journey. Exact source must receive independent Security review before consumption; no deployment or production write is implied.
